BUG #1: Missing 'name' attribute in Move class
-----------
File: src/pokemon_game/entities/move.py
Severity: MEDIUM
Status: FIXED

Problem:
  The Move class was missing a 'name' attribute, only having 'dbSymbol'.
  This caused AttributeError when code tried to access move.name.

Root Cause:
  Incomplete initialization of Move objects - dbSymbol is stored but 
  'name' was not extracted or provided.

Solution:
  Added 'name' attribute initialization in Move.__init__:
    self.name = move_data.get("name", self.dbSymbol)
  
  Updated to_dict() method to include name in serialization.

Test Coverage:
  ✓ UNIT-005: Verified moves have 'name' attribute
  ✓ INTEG-003: Confirmed in battle simulation

BUG #2: Incomplete Type Effectiveness Chart (Fire vs Ground)
-----------
File: src/pokemon_game/systems/battle.py
Severity: HIGH (affects game balance)
Status: FIXED

Problem:
  Fire-type moves were not marked as reduced effectiveness (0.5x) against 
  Ground-type Pokemon. This caused incorrect battle calculations.
  
  Example: Fire move vs Water/Ground dual-type should be:
    0.5 (vs water) × 0.5 (vs ground) = 0.25x
  But was calculating as 0.5 (vs water) × 1.0 (vs ground) = 0.5x

Root Cause:
  The TYPE_CHART dictionary for "fire" was missing the "ground" entry.
  Official Pokemon type chart has fire doing 0.5x damage to ground.

Solution:
  Added ground effectiveness to fire type:
    "fire": {
        "fire": 0.5, "water": 0.5, "grass": 2.0, "ice": 2.0,
        "bug": 2.0, "rock": 0.5, "ground": 0.5, "dragon": 0.5, "steel": 2.0,
    }

Test Coverage:
  ✓ UNIT-008: Type effectiveness calculation now correct
  ✓ INTEG-003: Battle damage calculations affected
  ✓ ROBUST-003: Pokemon stat calculations work properly
